# Search and agent discoverability

CypherX uses conventional, evidence-based discoverability rather than special AI markup. Important content remains in server-rendered HTML with semantic headings, native links and controls, descriptive routes, and visible article dates. The shared SEO component emits absolute self-referential canonicals, index/follow defaults, Open Graph/Twitter metadata, and page-appropriate JSON-LD.

Structured data is deliberately limited to visible page facts. Blog articles provide title, description, image, publication date, and an Article JSON-LD object. Other routes receive WebPage JSON-LD. No reviews, ratings, outcomes, service areas, or claims are generated by metadata.

`/llms.txt` is an optional, maintained orientation index to existing canonical pages. It is not required by Google and must not replace HTML, sitemap, canonical, or robots signals. `AGENTS.md` remains guidance for coding agents working in this repository; it is not copied into the generated website.

## Crawler policy

Existing Gatsby robots configuration is unchanged. Search and training crawler policies are independent; this project does not blanket-open training crawlers as an SEO tactic. Review generated `public/robots.txt` before deployment and use Search Console/Rich Results Test after release.

## Validation and maintenance

Use the pinned Node version (`nvm use`), then run:

```bash
npm run build
npm run check:discovery
```

The discovery check inspects generated HTML, not just source components. It checks route-specific metadata against page data, Article fields, valid source-post routes, local social-image files, complete service/project links, sitemap coverage, llms link targets, 404 indexing rules, contact labels, and the unchanged robots policy. Browser checks also cover mobile navigation, client-side metadata changes, and layouts from 320px to 1440px.

Only blog MDX nodes with a nonempty slug may produce blog detail pages. Keep all existing feature and portfolio routes reachable when changing featured homepage cards. Use existing, valid images or the brand fallback; do not invent image paths.

`gatsby-plugin-styled-components` provides server-rendered styles and stable component identifiers. Keep it enabled: without it, the Partners page had HTML class names with no matching hydrated styles. See the [official plugin instructions](https://www.gatsbyjs.com/plugins/gatsby-plugin-styled-components/).

Installation currently needs `npm install --legacy-peer-deps` because the existing `gatsby-plugin-gdpr-cookies` declares an older Gatsby peer range. That package was not upgraded here. The dependency audit reported 90 vulnerabilities during installation; dependency security remediation remains separate work. Do not treat a passing static-site build as a dependency security audit.

After deployment, verify the public URLs and use Search Console/Rich Results Test. Local checks cannot establish indexing, AI citations, or ranking improvements.
